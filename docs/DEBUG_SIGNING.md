# Debug signing — stability and fingerprints

JARVIS's debug build type does **not** use Android Gradle Plugin's default
debug signing (an auto-generated `~/.android/debug.keystore`, which differs
per machine/CI runner and would make the app's SHA-1 change on every build).
Instead, `app/build.gradle.kts` points `signingConfigs.debug` explicitly at a
keystore committed in this repo:

```kotlin
signingConfigs {
    getByName("debug") {
        storeFile = file("debug.keystore")   // app/debug.keystore, tracked in git
        storePassword = "android"
        keyAlias = "androiddebugkey"
        keyPassword = "android"
    }
}
```

`app/debug.keystore` is tracked in git (`.gitignore` has an explicit
`!app/debug.keystore` exception to the general `*.keystore` rule below it),
so every checkout — a local machine or a fresh GitHub Actions runner — signs
with the **exact same key**. This is why debug builds already update in
place on a device without an uninstall (CLAUDE.md phase 1), and why its
SHA-1 can be safely registered once in Google Cloud Console for Drive OAuth
(`docs/GOOGLE_DRIVE_SETUP.md`) — it will not change on the next CI run.

This is a standard AOSP-convention debug key (alias `androiddebugkey`,
password `android` for both store and key) — it identifies "this is a JARVIS
debug build," nothing more. It is **not** a secret and is **not** a
substitute for the release keystore (`jarvis-release.jks`, gitignored, held
only by the developer — see `docs/DECISIONS`) used for real distribution.

## Fingerprints

Extracted via:
```
keytool -list -v -keystore app/debug.keystore -storepass android -keypass android
```

| | |
|---|---|
| `applicationId` (debug, via `applicationIdSuffix = ".debug"`) | `com.simone.jarvismobile.debug` |
| SHA-1 | `B9:A7:FA:01:2E:4A:1F:04:DD:97:BD:0A:55:4D:99:B2:59:E9:DC:41` |
| SHA-256 | `33:01:8D:7F:10:C4:A1:AA:07:CC:1E:60:9B:A5:41:CA:F1:CD:31:8D:7E:67:05:56:F9:C8:26:D2:9B:07:C8:FB` |
| Source | `app/debug.keystore` (tracked in git, `signingConfigs.debug` in `app/build.gradle.kts`) |

Re-run the `keytool` command above after any change to `app/debug.keystore`
to confirm these are still current — but since the file is committed and
never regenerated by CI, they should only ever change if someone
deliberately replaces the file.

## Where the debug APK comes from

Every CI run on `main` or a `claude/**` branch (`.github/workflows/ci.yml`,
job "Core tests + Android debug build") assembles `app/build/outputs/apk/debug/app-debug.apk`
with this same key, uploads it as the `app-debug` artifact, and — on a push
or manual dispatch — republishes it to the repo's `latest-debug` GitHub
Release, so the newest debug build is always at a fixed URL:

```
https://github.com/<owner>/<repo>/releases/download/latest-debug/app-debug.apk
```

Because the signing key never changes, installing a new `latest-debug` APK
over an existing install works without uninstalling first.
